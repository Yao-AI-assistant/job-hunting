# 简历交付:Markdown 主版本 → docx

改稿定稿之后怎么变成能投的文件。**主版本永远是 Markdown**(可 diff、可回滚),docx 只是导出物。

## 目录约定

```
jobs/<公司>-<岗位>-简历改稿-v1.md      评审用:逐条 diff + 理由 + 待拍板项
jobs/<公司>-<岗位>-简历-投递版.md      定稿正文:只有简历本身,不带批注
jobs/<公司>-简历-<岗位>.docx           投递用
```

改稿和投递版**分两个文件**:改稿里的话是给你和他看的,投递版里一句批注都不能留。

## 导出

```bash
py tools/docx2md.py <原简历.docx>   <原简历.auto.md>    # 先读进来
py tools/md2docx.py <投递版.md>     <成品.docx>          # 再导出去
py tools/docx2md.py <成品.docx>     /tmp/_check.md       # 回读校验
```

依赖:`pip install python-docx`。

## 版式(已经在 `md2docx.py` 里固定)

- 纸张 A4,上下 1.6cm、左右 1.9cm;正文 微软雅黑 10pt,行距 1.2。
- 姓名 20pt 深蓝居中;紧跟两行联系方式 9.5pt 灰色居中。
- 小节标题 12pt 深蓝加粗 + 下边框。
- 列表用「• 」和「– 」,不用 Word 自动编号(跨平台渲染更稳)。
- **不用表格排版**。表格在 ATS 解析和邮件正文里最容易坏。

## 三个坑

1. **原简历内容可能全在文本框里。** python-docx 按段落读会读到空;`docx2md.py` 有 XML 兜底,读出来会有相邻重复行,去重后再用。
2. **中文标点别混 ASCII。** 「」、;、() 和 ,;() 混排时 Word 里字距会跳,统一用全角。
3. **数字后面一定带口径。** 「mAP 82%」不写数据来源和条件,面试一问就崩;写「实验条件下 mAP 约 82%(自建数据集)」。

## 交付前自查(逐条打勾)

- [ ] 每条经历都能指到一个证据编号
- [ ] 撤回过的数据没写回去
- [ ] 团队成果没写成个人成果
- [ ] 指标都带条件或写了「约」
- [ ] 项目名、公司名、时间与原始材料一致
- [ ] 全文没有跟这份 JD 无关的大段内容
- [ ] 导出后回读一遍,确认没有乱码、没有空段落

## PDF

需要 PDF 时用 Word(或 LibreOffice)另存;不要用网页打印,页边距和字体会跑。这一步留给本人或本地已有工具,不要为它临时装一堆依赖。
