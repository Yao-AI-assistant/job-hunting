# 评分方法

## 一、先拆 JD,再谈匹配

只读三样,别被整篇 JD 牵着走:

1. **业务目标**:这岗招进去干什么活(一段话概括)。
2. **前三项硬要求**:年限、学历、核心技术栈、必须有的项目类型。硬要求不能用「我很努力」换。
3. **加分项**:论文、竞赛、开源、外语、行业经验。

## 二、逐条对证据

| 列 | 写什么 |
|---|---|
| 要求 | JD 原文短句,不改写 |
| 现有匹配 | **带编号的证据**;没有编号的事实不写 |
| 缺口 / 补齐动作 | 缺口一句 + 一周内能做完的动作一句 |

证据强度三档,不许混:

- **强**:源码可查 / 论文原文 / 本人确认的实机记录。
- **中**:简历陈述但缺运行记录,或只有别人转述。
- **弱**:技能栏里的名词,没有对应任务。

评分时只认「强」和「中」;「弱」的条目写成「可以讲成方案,没做过」。

## 三、1–5 分怎么给

| 分 | 含义 |
|---|---|
| 5 | 硬要求全中,核心项目直接对口,只差公司信息 |
| 4 | 硬要求全中或只差一项软的,有一两处明显缺口可补 |
| 3 | 能面试但会被追着问,缺口不是一两周能补的 |
| 2 | 有一项硬要求过不去(年限差太多 / 核心栈完全不同) |
| 1 | 方向都不是 |

分数后面**必须跟一句人话结论**:「4/5,可投,值得认真准备」;不要「匹配度较高」。

## 四、两个常见错

- **按印象打分**:「感觉挺合适」→ 一定要落到硬要求逐条。感觉不可复用,表格可复用。
- **把可迁移说成有经验**:小目标检测能迁移到工业缺陷,但那是「我这样迁移」,不是「我做过产线」。

## 五、结论之外要写的三件事

1. **本次主讲 / 应弱化**:同一份经历,岗位不同讲法不同。写清这次该讲哪块、哪块别主动提。
2. **要跟本人确认的事**:地点、薪资、职级、行业偏好——这些不能猜。
3. **下一步**:细评 / 补材料 / 直接投 / 放弃,写一个。
