# 证据规则(简历与评分的事实底线)

这套规则的来源是「简历被追问就露馅」这个真实风险,不是道德洁癖。**任何一句写进简历的话,都要能被一份原始材料或一次本人确认撑住。**

## 五条底线

1. **已实现 / 已验证 / 本人完成,是三件事。** 源码支持「实现了」,运行记录和测试报告支持「验证了」,本人确认支持「我做的」。三者不互相顶替。
2. **正式论文结果、项目实验结果、简历概括分开存。** 近似数字不自动合并(94% 和 94.5% 是两个东西)。
3. **新技术可以讲成「我的方案」,不许包装成做过的项目。** 不会的就讲可迁移方法、前提条件、验证路径——这比背名词更得分。
4. **原始材料不改写,改动走新增文件。** Markdown 当主版本,要 Word 再导出。
5. **新事实先进证据库,再同步到题库和简历。** 只改某一份问答会导致口径不一致,面试里最容易被抓。

## 证据库长什么样

每条经历一张卡:

```
E编号 / 背景目标 / 已有产物(来源标注) / 结果(指标+口径) /
个人职责(独立实现|共同开发|接入开源|调参验证) / 可说明能力 / 待确认
```

来源标注用这几种:`[源码]` `[原文]` `[简历]` `[本人确认]` `[待确认]` `[补充知识/方案]`。

## 撤回机制(重要)

本人纠正过的事实,**当场撤回并留记录**,不要偷偷改掉:

```
[本人确认·撤回] 2026-10-26:此前称本人完成的 X 增强,实际是其他项目的做法,
本人只参与收尾。关联的指标 +5pp 暂停作为个人成绩引用,待独立核实。
```

撤回记录的作用:防止下次又被写回去,也防止 agent 把旧材料当新事实。

## 语境纪律

- 团队项目规模(如「累计约 2.5 亿」)不等于个人负责的预算,也不等于团队人数。
- 论文署名要分清一作、通讯、共同作者的具体分工。
- 实习不算正式工龄;科研经历单列;三段不许相加自称「N 年工业经验」。
- 数字没口径(是 RMSE 还是最大值?测试集多大?)就写「约」,并在面试里主动说口径。
