# 定向改简历

## 铁律

**只改他点头的那一份 JD。** 不做「通用升级版」——通用版会稀释重点,谁都投不好。

## 五步

1. **摆两张表**
   - JD 前三项硬要求 + 加分项;
   - 证据库里能对上的卡片(编号 + 一句话)。
   对不上的写「缺口」,不是「用别的经历硬凑」。
2. **定主线**:这一份简历只用 1–2 个项目做主角,其余一行带过。同一份经历在不同岗位里讲法不同(检测 / 配准 / 工业 / 机器人 / 应用)。
3. **改写**:每条只做三件事之一——**换成 JD 的词**、**补上口径**、**删掉无关的**。
   - 换词:JD 说「缺陷检测」,别写「小目标检测」,写「小目标/细粒度缺陷检测(迁移)」。
   - 补口径:指标后面加测试条件,或者干脆降级成「约」。
   - 删:和这份 JD 无关的论文、无关的技术栈,删。
4. **出 diff**:改了什么、为什么、风险在哪,逐条给他看。**他自己决定留不留。**
5. **回写**:这次用到的、梳理出的事实,按 `references/evidence-rules.md` 回写证据库。

## 不许做的

- 不新增没做过的项目、头衔、团队规模、预算数字。
- 不把「协作完成」写成「独立完成」。
- 不把撤回过的内容写回去。
- 不为了对齐关键词堆一串没碰过的框架名。

## 输出的三种格式

| 用途 | 格式 |
|---|---|
| 改稿评审 | Markdown diff(原句 → 新句 + 理由) |
| 投递 | 由 Markdown 导出 Word/PDF,版式单独维护 |
| 面试自用 | 一份「这条写了什么、背后证据是哪条、会被追问什么」的对照表 |
